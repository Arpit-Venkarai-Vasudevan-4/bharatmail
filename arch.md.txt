PhoneMail is a modular monolith: an Express/TypeScript REST API, PostgreSQL 16, and separately deployed Expo/Vite clients. PostgreSQL is the source of truth for immutable account UUIDs, phone-derived addresses, auth/session state, conversations, per-user mailbox state, drafts, contacts, aliases, privacy, uploads, outbox jobs, and account-scoped sync. SQL migrations run before the API accepts requests.

Authentication supports passwords and an AuthProvider boundary with Twilio Verify OTP. A local OTP mode is a development simulation only. Direct conversations use stable account identity; groups are independent conversation records. Messages and per-user mailbox state are separate, replies are constrained by a unique parent-message rule, and recipient delivery state is modeled separately from local message commitment.

REST clients use bounded pages and materialized snapshots with a final-page incremental handoff. Attachment bytes live under the configured storage directory, persisted by the Compose backend volume. The transactional outbox is intended for bounded provider delivery, but live telecom signup/notification adapters and complete crash/reconciliation behavior remain Stage 2 gaps. The system does not claim Internet SMTP interoperability, exactly-once external delivery, end-to-end encryption, active malware scanning, or distributed scale.
